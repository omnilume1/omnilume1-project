# Supabase Database Files

This folder contains the **complete database definition** of the shared Supabase project (project ref: `cqmqliqfrasaxzuyeshc`).

## THE RULE

> **`01_schema.sql` is the single source of truth.** It is always regenerated from the live database with `pg_dump` — never edited by hand. If it disagrees with the database, the database wins.

## Contents

| Path | Purpose |
|---|---|
| `01_schema.sql` | **Authoritative rebuild file.** Full schema: all tables, columns, indexes, functions, and RLS policies. Generated by `pg_dump --schema-only`. |
| `POLICIES.md` | Human-readable listing of every Row Level Security policy (review only — do not execute). |
| `archive/` | One-off SQL scripts already applied to the live database (e.g. `reconcile.sql`). Kept for history only — never run again. |

## How to rebuild the database on a fresh Supabase project

1. Create the new project
2. Open **SQL Editor**
3. Paste the entire contents of `01_schema.sql` and run it
4. Done — all tables, policies, and functions are recreated

## Workflow after ANY database change

Whoever changes the database (Supabase SQL Editor or migration script):

1. Tell the other person
2. Regenerate the dump: `pg_dump --schema-only --no-owner --no-privileges -n public -f supabase/01_schema.sql` (connection details in the team chat — never committed)
3. `git add . → git commit -m "sync schema" → git push`

This keeps the repo able to rebuild the entire backend from scratch at all times.

## Never commit

- Database passwords or connection strings
- Service-role keys or anon keys (those live in `.env.local`, which is gitignored)
